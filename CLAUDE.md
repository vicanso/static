# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`static-serve` is a high-performance static file server written in Rust (edition 2024, Axum) aimed at serving frontend static assets. Storage is abstracted through `opendal` (local filesystem, S3, FTP, MongoDB GridFS). Features: TinyUFO LRU cache, gzip/brotli/zstd compression, pre-compressed file support, ETag/304, HTTP range requests + If-Range, directory auto-indexing, HTML content replacement, CORS, Basic Auth, IP allow/block lists, per-IP rate limiting, redirects, nosniff default, Prometheus `/metrics`, text/JSON access logs, configurable graceful SIGTERM drain.

## Commands

```bash
make dev      # cargo watch, STATIC_PATH=./assets, RUST_LOG=INFO  (needs cargo-watch)
make lint     # typos + cargo clippy --all-targets --all -- --deny=warnings
make fmt      # cargo fmt
make release  # cargo build --release  (LTO/strip/panic=abort come from Cargo.toml [profile.release])
make bloat    # cargo bloat --release
```

Unit tests live in-module under `#[cfg(test)] mod tests` in every module (pure logic: range parsing, `Accept-Encoding` negotiation, conditional-request precedence, `If-Range`, cache-key formatting, identity `ruled_out` sets, cache weights, error→status mapping, `..` detection, CORS policy parsing, XFF resolution, latency bucketing, the token-bucket math and shard cap). Run all with `cargo test`, or one with `cargo test <name>`. There is no `tests/` integration dir yet. `unwrap_used = "deny"` applies to test code too, so tests use `assert!`/`assert_eq!`/`matches!` and infallible constructors rather than `.unwrap()`; the rate limiter exposes a private time-injectable `check_at(ip, now)` so its refill math is tested deterministically without a real clock.

`make lint` is the gate that matters and must pass. Beyond `--deny=warnings`, `Cargo.toml` sets `[lints.clippy] unwrap_used = "deny"` — **do not use `.unwrap()`**; propagate via the `Error` type / `Result`. Run `cargo clippy` (or `make lint`) before considering any change done.

## Architecture

Seven Rust modules (`src/*.rs`) plus compile-time HTML templates. Request flow: `main.rs` fallback route → `serve.rs static_serve()`/`get_file()` → cache check → path validation → opendal `stat` → directory/file handling → header generation → ETag/304 → body (buffered or streamed).

- **`config.rs`** — All `STATIC_*` env vars via `envy`, parsed once in `Config::new()`. **On any parse error it logs and `std::process::exit(1)` — deliberately no silent fallback to defaults.** Duration/byte-size fields (`timeout`, `cache_ttl`, `not_found_cache_ttl`, `html_cache_ttl`, `read_max_size`, `shutdown_delay`, `cache_max_bytes`, `backend_read_chunk`) are `Option<String>` parsed by hand (`parse_duration_or_exit`/`parse_bytesize_or_exit`; the two short cache TTLs additionally exit when set above 5 minutes; `backend_timeout`/`backend_io_timeout` use `parse_optional_duration_or_exit` → `None` when unset, meaning "do not attach the layer"); `STATIC_CORS_MAX_AGE` is likewise validated (digits only) with exit-on-bad-value. IP lists have two parsers: `parse_ip_list` (lenient, drops invalid entries — allow/block/exempt lists) and `parse_ip_list_strict_or_exit` (`STATIC_TRUST_PROXY` only — a silently dropped proxy CIDR would distrust the real proxy, worse than failing to boot). `STATIC_STARTUP_CHECK` parses to the `StartupCheck` enum (`warn` default / `strict`, anything else exits). `STATIC_CORS_ALLOW_ORIGIN` is pre-parsed into the `CorsAllowOrigin` enum (`Any` / `EchoAny` / `Single` / `List`, invalid header values dropped with a warning) so requests never re-split it. `not_found_page_ttl` is derived here: max(not_found_cache_ttl, html_cache_ttl), or 10s when both are zero. **Do not convert these back to `#[serde(deserialize_with)]`**: combined with the struct's `#[serde(default)]`, `envy 0.4` then fails whenever those vars are absent, which previously made the entire config silently revert to defaults. Prefix-scanned vars (`STATIC_HTML_REPLACE_*`, `STATIC_RESPONSE_HEADER_*`, `STATIC_CACHE_CONTROL_EXT_*`, `STATIC_REDIRECT_*`, `STATIC_BASIC_AUTH_*`) are handled by a manual `std::env::vars()` loop, not the `EnvConfig` struct.
- **`storage.rs`** — `opendal` abstraction; one `Storage` in a `OnceLock`. Backend auto-detected from `STATIC_PATH` (read here, separately from `config.rs`): bare path → local FS; `http(s)://...?bucket=` → S3; `ftp://` → FTP; `mongodb://` → GridFS. **Backend resilience layers** (`RetryLayer`/`TimeoutLayer`) are wired in at startup via `init_backend_resilience()` (called from `main()` with the parsed `Config`, into a `OnceLock`) and applied by `apply_resilience()` to every operator (local + remote). All off unless configured. Layer order is load-bearing: `TimeoutLayer` is attached *inside* `RetryLayer` (timeout applied first on the type-erased `Operator`), per opendal's requirement, so each retry attempt is independently bounded; `with_timeout` covers non-IO ops (`stat`), `with_io_timeout` covers streaming reads. Local FS path is canonicalized; `validate()` (async) blocks path traversal (resolved path must stay under root). For local FS it does a lexical `..` check (always on) plus a `canonicalize()` — run via `spawn_blocking`, it's a blocking realpath — to catch symlinks escaping the root; the latter is skippable via `STATIC_DISABLE_SYMLINK_CHECK=true` (read once into a `OnceLock`, exit-on-bad-value) for symlink-free asset trees that don't want the per-miss syscall. **Remote backends reject any `..` path segment** (opendal's `normalize_path` doesn't resolve `..`, and an FTP server would). `Storage::reader()` opens streaming readers, applying `STATIC_BACKEND_READ_CONCURRENT`/`_CHUNK` (`init_read_tuning`, a `OnceLock`) as opendal `reader_with().concurrent().chunk()` when concurrency > 1.
- **`serve.rs`** — Core handler. TinyUFO LRU cache; **directory autoindex listings are never cached; HTML is uncached by default** (mutable across deploys/requests via opendal backends) but opt-in cacheable via `STATIC_HTML_CACHE_TTL` (≤5m; clients still get `no-cache` — only backend reads are amortized). **404s are negative-cacheable** via `STATIC_NOT_FOUND_CACHE_TTL` (≤5m): a not-found load stores a `CacheValue::NotFound` entry under the identity (empty-encoding) key — 404 doesn't vary by Accept-Encoding — and a later hit replays the 404 without touching the backend; only genuine not-founds are stored (never the request-specific 301). Positive entries are stored under the *request* path (`params.file`), not the index-joined path, so a directory request hits the entry it stored. **Directory index resolution is optimistic**: a directory-style *candidate* (`params.file` empty or ending in `/` — deliberately not `request_path`, since the main.rs fallback loop re-enters with `index.html` while the request path still ends in `/`, and probing `index.html/index.html` is ENOTDIR) with autoindex off and an index configured stats `<dir>/<index>` directly (one backend round-trip instead of stat-dir-then-stat-index), falling back to the directory stat only on a not-found miss; the trailing-slash guard is load-bearing (a slash-less directory must 301 first, which needs the directory's own stat). Buffers files `< STATIC_READ_MAX_SIZE` (default 250KB), streams larger ones (via opendal's `into_bytes_stream`, bounded to the stat size — no AsyncRead adapter re-copying chunks); HTML is always buffered (the replacer needs it) but HTML `>= read_max_size` is never cached, and HEAD of HTML with a replacer reads the body so Content-Length matches GET; supports range/206 (a single range streams or slices one body; multiple comma-separated ranges return a `multipart/byteranges` body assembled in memory via `build_multipart_byteranges`, capped at `MAX_RANGES` = 100 parts *and* `MAX_MULTIPART_TOTAL_BYTES` = 8 MiB total payload (ranges may overlap, so the count cap alone wouldn't bound memory), excess → full 200; multi-range on a Content-Encoded representation falls back to a full 200 since the envelope can't itself be encoded), `If-Range`, 304, per-extension cache-control, and `.br`/`.zst`/`.gz` pre-compressed negotiation (q-value aware via `EncodingPrefs` — `br;q=0` is honored as a refusal). **The in-memory cache key is encoding-aware** (`encoding_cache_key` = `"<path>\0<encoding>"`; identity = empty suffix), so pre-compressed responses ARE cached — each negotiated encoding is a distinct entry, and a hit returns the exact bytes + `Content-Encoding` without re-`stat`ing the path or probing its `.br`/`.zst`/`.gz` siblings. A lookup probes the client's accepted encodings (br>zstd>gzip) then identity; first usable hit wins. **Identity entries carry a `ruled_out` encoding bitmask** (encodings known to resolve to identity: sibling probed-absent or not applicable, *and* cached compression not applicable or tried-and-rejected — `identity_ruled_out`); with `precompressed` or `compress_cache` on, an identity hit for a client accepting an encoding outside that set is treated as a miss, and the reload merges the old set (`prior_ruled_out`). Without this, whichever client loaded first (e.g. curl with no Accept-Encoding) pinned identity and hid the `.br` sibling / cached compression for the whole TTL. **Streamed entries (`body == None`) are revalidated on every hit** (`still_fresh`: one `stat` of `read_file` compared against the stored `StatFingerprint` of size/mtime/backend ETag); a mismatch removes the entry (`remove_from_cache`) and reloads — otherwise a file overwritten in place streams new bytes under stale Content-Length/ETag. Cache weights: 1 per entry, or body KiB when `STATIC_CACHE_MAX_BYTES` is set (`init_cache` at startup; TinyUFO weights are u16). **If you add a new way the served bytes vary by request, fold it into the cache key** or you'll serve the wrong variant. **Cached dynamic compression** (`STATIC_COMPRESS_CACHE`, off by default): a cacheable buffered body of a compressible type is compressed once in `load_file` (`compress_body` — async-compression, the same crate/level mapping the CompressionLayer uses, **including tower-http's brotli `Default` → quality 4 override** in `async_compression_level` (async-compression's own default is q11, ~10x slower); it runs on the blocking pool via `spawn_blocking` + `Handle::block_on` because an in-memory encoder never yields and would monopolize a worker; `is_compressible_content_type` is shared with main.rs's `Compressible` predicate) and stored under the encoding-aware key; only when `will_cache`, never over a pre-compressed sibling or backend Content-Encoding, identity kept when compression doesn't shrink. The sibling `stat` probe is gated on `params.precompressed` specifically so compress_cache (which also needs Accept-Encoding) doesn't pay probe round-trips. Content-Length is pushed *after* the body is known (HTML replacement / compression change the byte count; X-Original-Size stays the stat size). Autoindex renders at most `AUTOINDEX_MAX_ENTRIES` = 10,000 rows (then a truncation notice) — listings are rebuilt per request and never cached, so unbounded directories would allocate multi-MB HTML per hit; the listing is consumed as an opendal `lister` stream (`futures_util::StreamExt`) so the cap also stops backend paging. opendal lists the directory itself (root as `/`, a subdir as `sub/`) — it's skipped by comparing paths, not by name length. Metadata-only entries (large/streamed files, `body == None`) are cached too so a hit skips the `stat`+sibling probes; HEAD responses are never cached (their body is always None). **Cache misses are single-flighted** (`get_file` → `Flight`/`INFLIGHT`): concurrent misses for the same `singleflight_key` (path + accepted-encoding bits + HEAD-ness) collapse to one leader load; followers share the leader's `Arc<FileInfo>` (streamed bodies still open their own reader per follower). Only `Ok` results are shared — errors/redirects fall through to an independent load, so request-specific data (e.g. a 301 `Location` built from the request path) is never cross-fed. The leader's slot is RAII-guarded (`FlightGuard`): if the leader future is dropped mid-load (client disconnect), the guard's `Drop` removes the INFLIGHT entry and wakes followers, so a cancelled leader can't leave a dead flight that would hang every later request for that key. File responses always carry `Vary: Accept-Encoding` (the global CompressionLayer may compress on the fly regardless of `STATIC_PRECOMPRESSED`). `If-Range` uses strong validators only — a weak ETag never satisfies it, and a date must *exactly* equal Last-Modified (RFC 9110 §13.1.5) — otherwise the Range is ignored and a full 200 is returned. **304 precedence**: `not_modified()` (shared by `load_file` and `static_serve`) uses If-None-Match *alone* when present (RFC 9110 §13.2.2; weak comparison, `W/` ignored both sides) and If-Modified-Since only when it is absent — falling through to the date on an ETag mismatch 304'd changed files under reproducible-build constant mtimes. `X-Original-Size` is rewritten to the bytes actually sent: `0` for 304/HEAD/416, the range/multipart length for 206 (`set_logical_size`). **Conditional loads skip the body read** when the request's If-None-Match/If-Modified-Since already guarantee a 304 *and* the entry wouldn't be cached anyway (uncached-by-default HTML, or cache off): `load_file` consults the same predicate functions (`if_none_match_hit`/`if_modified_since_hit`) that `static_serve` re-checks, so the decisions can't drift; such a body-skipped result returns `share=false` and is never published to single-flight followers (they'd stream it raw, bypassing the HTML replacer) nor cached. Autoindex file names are HTML-escaped and percent-encoded (`html_escape`) — they are attacker-influenced. The `.wasm`/`.mjs` MIME override only fills in when the type is otherwise undetermined (never clobbers a backend-set Content-Type). Cache hits/misses are counted via `crate::metrics`.
- **`error.rs`** — `Error` enum (`Unknown`, `InvalidFile`, `Timeout`, `NotFound`, `Forbidden`, `Openedal`, `ParseUrl`). `Error::status()` maps: not-found → 404 (**`is_opendal_not_found` also treats ENOTDIR as not-found** — opendal folds it into `Unexpected`, so `/file.txt/x` would otherwise be a server error and abort the SPA fallback), opendal `PermissionDenied` → 403, `RateLimited`/temporary → 503, other opendal → 500, `Timeout` → 504, `InvalidFile` → 400. Backend errors are never 4xx-masked (they used to be 400, hiding outages from 5xx alerting). `IntoResponse` renders a **built-in HTML error page for every error status**; internal/opendal detail (paths, OS errors) is **never** sent to the client, only logged server-side. Override via `STATIC_ERROR_PAGE` (filesystem path; template uses `{{STATUS}}`/`{{REASON}}`), resolved once at startup by `init_error_template()` (called from `main()`); set-but-unreadable → process exits. Independent from a user `404.html` in `STATIC_PATH` (404-only, served verbatim, takes precedence for 404s; the lookup — body or absence — is cached by `serve::not_found_page` for max(not_found_cache_ttl, html_cache_ttl), zero = uncached, and only definitive outcomes are cached, never transient backend errors).
- **`metrics.rs`** — Process-memory `AtomicU64` metrics rendered as Prometheus text: monotonic counters (requests, responses by status class, response bytes, cache hits/misses), a `static_serve_request_duration_seconds` **histogram** (per-bucket atomics summed cumulatively at render; observed in `track_metrics` as time-to-produce-the-response, **not** including streamed-body transfer), and **gauges** `static_serve_cache_entries` (live occupancy) + `static_serve_cache_capacity` (configured max). The occupancy gauge is maintained in `serve.rs`'s `set_file_to_cache` (TinyUFO has no `len()`): a pre-`put` `get` decides if the key is new (+1), and `put`'s returned evicted-entries `Vec` gives the count to subtract — correct across both fresh inserts and re-caches of logically-expired-but-still-present keys. Capacity is set once at startup via `set_cache_capacity`. Exposed at `GET /metrics` when `STATIC_METRICS=true` (default). **`STATIC_METRICS` is a master switch** (`set_enabled` → the `ENABLED` `OnceLock<bool>` — write-once at startup, no runtime toggle): when false, every `record_*` returns immediately *and* callers skip their own metrics-only setup (`track_metrics` skips the two `Instant::now()` clock reads; `set_file_to_cache` skips the gauge's pre-`put` `get`; `record_cache_remove` saturates) — so disabling metrics removes both the route and the per-request collection cost, not just the route. No external deps; `Relaxed` ordering (scrape metrics need no cross-counter consistency).
- **`rate_limit.rs`** — Per-IP token-bucket limiter, **sharded** (64 `Mutex<State>` shards by `RandomState` hash of the IP; each shard sweeps its own idle buckets every 60s, and is hard-capped at `MAX_BUCKETS_PER_SHARD` — at the cap it re-sweeps at most once a second, then lets unseen IPs through untracked (fail-open) so spoofed-XFF floods can't grow memory unboundedly) (`STATIC_RATE_LIMIT` req/sec, `STATIC_RATE_LIMIT_BURST` capacity; `0` = disabled, the default). `STATIC_RATE_LIMIT_EXEMPT` (comma-separated IPs/CIDRs, parsed by `config.rs`'s `parse_ip_list`) bypasses the limiter — the exemption is enforced in `main.rs` `serve` (where the `Config` IpNet list and resolved `ClientIp` live), not in this module. A single global `OnceLock<Option<RateLimiter>>`; `check(ip)` returns `Some(retry_after_secs)` to reject with 429 or `None` to allow — **lock-free and zero-cost when disabled** (returns before touching the mutex). Lazy float refill per request; tests set the `shard_cap` field directly to exercise the cap. No new deps — deliberately not `tower_governor`, so limiting reuses the caller's XFF-aware `ClientIp` rather than a second IP-extraction path. The burst clamps to `>= 1` and the limiter is only built when rate `> 0`, so the refill division never hits a zero rate.
- **`main.rs`** — Axum router: `GET /health`, optional `GET /metrics`, catch-all `fallback(serve)` (a bare handler, **not** `get(serve)`, so `OPTIONS` reaches the handler for CORS preflight; other non-GET/HEAD methods get 405). Middleware order matters (outermost→in): `track_metrics` (records a sample when metrics are enabled, and always strips the internal `x-original-size` header so it never leaks to clients) → optional `access_log` → `HandleErrorLayer` → optional `CompressionLayer` (only when `compress_min_length > 0`; `0` disables compression entirely) → timeout → handler. In `serve`: IP block/allow → **per-IP rate limit (bare 429 + `Retry-After`, after IP control so blocked IPs allocate no bucket state; IPs/CIDRs in `STATIC_RATE_LIMIT_EXEMPT` skip it; no-op when disabled)** → **CORS preflight / method gate (before Basic Auth, so a credential-less browser preflight is not 401'd)** → Basic Auth → redirects → file serving. **`ClientIp` resolution is trust-gated by `STATIC_TRUST_PROXY`** (comma-separated proxy IPs/CIDRs, parsed strictly in `config.rs` — invalid entry exits — and injected into a `main.rs` `OnceLock` via `init_trust_proxy` because the extractor also runs in `from_fn` middleware whose state is `()`): unset keeps the historical trust-all order (XFF leftmost → X-Real-Ip → socket); set means forwarded headers count only when the direct peer is a trusted proxy, and the client IP is the *rightmost* non-trusted XFF hop (`client_ip_from_xff`, unit-tested in main.rs) so a client-prepended forged entry can't spoof IP control/rate limiting. `apply_common_headers` adds `STATIC_RESPONSE_HEADER_*`, the `X-Content-Type-Options: nosniff` default (skipped if you set it yourself), and CORS headers to every served/redirect/404 response. **Startup is fail-fast on storage**: `run()` calls `storage::get_storage()` before binding (operator construction is pure config validation, no I/O — a bad `STATIC_PATH` exits instead of 500ing every request) and then runs an `Operator::check()` connectivity probe (one root `list`); probe failures are network-class and can self-heal, so `STATIC_STARTUP_CHECK=warn` (default) only logs while `strict` exits. Accepted sockets get `TCP_NODELAY` (`ListenerExt::tap_io`; axum 0.8 leaves Nagle on). `access_log` stores the resolved `ClientIp` in request extensions and the extractor checks there first, so XFF is parsed once per request. `warn_spoofable_client_ip` logs at startup when allow/block lists or rate limiting are on without `STATIC_TRUST_PROXY`. Graceful SIGTERM: `/health` returns 503 (Service Unavailable, not 500 — LBs treat it as a temporary drain, not an alert-worthy error) for a `STATIC_SHUTDOWN_DELAY` drain window (default 5s) before shutdown. `LOG_FORMAT=json` switches the tracing subscriber to JSON.

**Templates:** `src/templates/error.html` and `src/templates/autoindex.html` are embedded at compile time via `include_str!` (paths relative to `src/error.rs` / `src/serve.rs`). Runtime placeholders: `{{STATUS}}`/`{{REASON}}` (error), `{{CONTENT}}` (autoindex). Edit the `.html` files directly — no Rust change needed.

## Configuration & Non-Obvious Behavior

Full env var reference lives in `README.md` / `README_zh.md`. Key behaviors not obvious from the code:

- HTML always gets `Cache-Control: no-cache` regardless of `STATIC_CACHE_CONTROL`, and is not cached in memory unless `STATIC_HTML_CACHE_TTL` (≤5m) opts in — that caches server-side only; the client header stays `no-cache`.
- `STATIC_NOT_FOUND_CACHE_TTL` (≤5m, default off) negative-caches 404 lookups: a file created inside the window keeps 404ing until the entry expires. With `STATIC_FALLBACK_*_404`, each missing fallback candidate gets its own negative entry.
- Cache-Control precedence: HTML `no-cache` > backend-provided > `STATIC_CACHE_CONTROL_EXT_<ext>` > `STATIC_CACHE_CONTROL`.
- `STATIC_COMPRESS_MIN_LENGTH=0` removes the compression layer entirely (it does not mean "compress everything").
- `/health` and `/metrics` are separate routes — they bypass Basic Auth, IP access control, and rate limiting. `STATIC_METRICS=false` removes the `/metrics` route **and** disables per-request metric collection (the `track_metrics` layer still runs to strip the internal `x-original-size` header, but records nothing).
- CORS preflight (`OPTIONS`) is answered before Basic Auth so a credential-less browser preflight is never 401'd; it still passes IP access control.
- `X-Content-Type-Options: nosniff` is added by default (`STATIC_CONTENT_TYPE_NOSNIFF=true`) but never overrides a value you set via `STATIC_RESPONSE_HEADER_*`.
- File responses always carry `Vary: Accept-Encoding`. `Vary: Origin` is appended whenever the CORS config is origin-dependent (multi-origin allowlist, or `*` with credentials) — **including non-matching requests**, whose ACAO-less response must not be cached as the variant for every origin; a single fixed origin or bare `*` never varies. Autoindex listings are `no-cache` and never stored in the in-memory cache.
- The request-timeout page (504) is generated outside the compression layer (uncompressed); other error pages are inside it.
- The custom `404.html` lookup is cached for 10s by default (or the larger short-cache TTL when set). Error responses do not pass through `apply_common_headers`, so they carry no CORS/nosniff headers.

## Conventions

- Conventional Commits (`feat:`, `fix:`, `chore:`); history commits directly to `main`.
- `README.md` and `README_zh.md` are a mirrored pair — keep structure and content in sync when changing config or behavior docs.
- **Bring cross-module items into scope with `use`; do not call them through an inline fully-qualified `crate::...` path.** Write `use crate::metrics;` once at the top and call `metrics::record_cache_insert(...)`, not `crate::metrics::record_cache_insert(...)` at the call site. (`use crate::module;` and calling `module::item()` is preferred over importing bare functions, so the originating module stays visible at the call site — this matches `main.rs`.) `crate::` belongs only in `use` statements.
